# SiteLens 设计系统

这份设计系统约束 SiteLens 的页面设计、设计稿生成与后续实现，确保首页、报告页和公开拆解页保持同一套增长顾问品牌语言。

## 产品语境

- 产品：SiteLens，AI 网站增长顾问。
- 核心承诺：帮助创业者理解网站为什么没有带来客户，并给出有证据的下一步行动。
- 主要用户：独立开发者、小企业主、设计师与营销人员。
- 关键页面：`/` 首页、`/report/{id}` 诊断报告、`/teardowns` 公开案例库。
- 信任原则：展示分析框架、证据、影响和改法；不把 AI 当作唯一卖点，不制造无法验证的精确感。

## 视觉方向

当前系统是编辑型、证据驱动、克制直接的视觉语言：像一份来自增长团队的短咨询报告，而不是通用 AI 工具后台。

- 纸张感浅灰背景与深绿内容面板形成结构对比。
- chartreuse 是唯一的高亮色，用于 CTA、重点文字、评分进度和偏移阴影。
- 使用细线、编号、等宽标签和不对称双栏建立“方法论 + 证据”的秩序。
- 几乎不使用圆角；不使用渐变、玻璃拟态、紫色 AI 光效或装饰性插画。
- 标题要紧凑、有判断力；正文要短而清楚；避免空泛的营销口号。

## 字体与排版

- 正文与标题：`Geist Variable`。
- 标签、元数据、编号：`Geist Mono Variable`。
- 标题字号使用 `clamp()`，字距通常在 `-0.05em` 到 `-0.10em` 之间，行高约 `0.92` 到 `1.05`。
- eyebrow、section label、evidence label 使用 9–10px 等宽大写，字距约 `0.08em`–`0.13em`。
- 正文优先 13–17px，行高 1.45–1.65；每段保持短小。
- 重要结论可以使用斜体和 accent，但不得让整段文本变成装饰。

## 布局与响应式

- 主容器：`.shell`，最大宽度 `1180px`；桌面左右留白 32px，移动端 16px。
- 顶部导航最小高度 76px；移动端 68px。
- 首页 hero 默认采用不对称双栏，文案与 URL 表单在左，证据图片在右。
- 报告页使用“摘要 + 评分”双栏、“证据条 + 问题列表 + 解锁行动”的顺序。
- `840px` 以下切单栏；`760px` 以下深度报告切单栏；`560px` 以下压缩导航、输入表单和证据栅格。
- 大区块使用 80–150px 的垂直留白，依靠细线和标题分组，而不是大量卡片。

## 核心组件语法

- Wordmark：SiteLens 文字 + 25px chartreuse 方形 `S` 标记。
- 导航 CTA：chartreuse 实心按钮，带少量上移反馈。
- URL 输入：深绿输入行 + chartreuse 提交按钮 + 10px 实心偏移阴影。
- Analysis Process：等宽编号列表，展示正在理解产品、检查文案、审核信任元素等步骤。
- Score Ring：chartreuse conic-gradient 评分环，中心显示分数；必须同时提供上下文或 benchmark，避免分数成为孤立结论。
- Evidence Strip：四列或移动端两列的证据概览，突出 headline、受众、CTA、信任等事实。
- Issue Card：编号、问题、严重度、Evidence、Why it matters、How to fix、Example rewrite。
- Upgrade Card：深绿 panel、价格和清晰的 Deep Growth Report 价值，不使用夸张收益承诺。
- Framework List：Positioning、Clarity、Trust、Conversion、Authority 五项方法论。
- Teardown Card/页面：公开案例先给结论，再给证据与 action plan，风格与报告页一致。

## 交互与信任

- 先展示证据，再展示判断；任何结论都尽量能指回页面文案、DOM 结构、CTA 位置或缺失信任元素。
- 加载状态显示分析过程，不使用“AI 正在施法”一类拟人化黑盒文案。
- 对不确定信息使用“未检测到”“无法确认”或“需要人工验证”，不要伪造精确度。
- CTA 动效只做轻微位移；尊重 `prefers-reduced-motion`。
- 所有输入、按钮和链接保持清晰的 `:focus-visible` 状态。
- 报告可以导出和分享，但不能把“AI 建议”包装成保证转化结果。

## 生成与实现约束

- 设计稿必须引用本文件、`.superdesign/init/` 上下文和对应页面源码。
- 首次生成现有页面时，先做像素级复现，再从复现稿分支出变体。
- 设计阶段不直接改业务代码；只有用户批准具体设计方向后，才进入实现。
- 新页面优先复用现有 token、字体、容器和组件语法；如果确实需要新增 token，必须说明原因并同步到本文件。
- 不添加与 SiteLens 核心价值无关的 dashboard、竞品监控或企业级功能视觉。
