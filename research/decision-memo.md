# AI Website Critic 前期决策备忘录

**日期**：2026-08-10
**结论**：先做小规模付费验证，不立即进入完整 SaaS 开发。

## 为什么不是直接 Go

竞品扫描已经证明这类产品有公开需求表达和成熟的免费→付费报告模式，但也证明当前功能列表不是空白：Cruelx、Web Anatomy 和 Conversion Probe 已经覆盖了相近的 URL 分析、评分、视觉/结构审计、优先级修复和一次性报告。

因此现在直接堆 Next.js、Playwright、支付、PDF、SEO 页面和订阅，会先验证“能不能做出来”，而不是验证“用户是否愿意为这份报告付费”。

## 决策

### 现在做：小规模付费验证

用人工或半自动流程交付 15–20 个目标用户的网站诊断，验证以下四件事：

1. 用户是否愿意提交 URL。
2. 报告是否被认为具体、可信、可执行。
3. 用户是否愿意留下邮箱接收报告。
4. 用户是否愿意购买 $9–$19 的一次性 Deep Audit。

这不是完整产品开发，不需要先做订阅、PDF 自动化、SEO 内容矩阵或竞品监控。

### 暂不做：完整 SaaS

在没有真实购买之前，暂缓：

- 自动化 45+ 页 PDF。
- $19/月订阅和网站变化追踪。
- 代理商白标和多站点工作台。
- 五个 SEO 入口页。
- 复杂竞品定位分析。
- 视觉 AI 的正式产品承诺。

## 建议的验证实验

### 实验流程

1. 选择 15–20 个 Indie Hacker/小型 SaaS 创业者的公开首页。
2. 用统一 rubric 生成一页免费诊断：一个总判断、最大问题、三项 quick wins。
3. 展示一份付费 Deep Audit 样例，明确包含：所有主要问题、页面证据、转化影响、文案改写和 48 小时/7 天/30 天行动计划。
4. 提供真实一次性付款入口，测试 $9、$19 其中一个或两个价格点。
5. 手工交付或半自动交付付费报告，记录交付时间和用户反馈。

### 建议的判断门槛

以下是用于做决策的实验门槛，不是市场基准，产品负责人可在实验前调整：

| 结果 | 决策 |
|---|---|
| 20 个合格提交中出现至少 3 个真实付费，且报告质量评分达到 4/5 左右 | 进入产品 V1 开发 |
| 有 1–2 个付费，但用户集中质疑价格、准确性或目标用户 | 先改定位/价格/报告，再重复小实验 |
| 没有付费，或用户认为建议泛泛且不可信 | 暂停开发，重新审视问题和差异化 |

不建议把“1000 次分析”作为第一道闸门。没有明确流量来源时，绝对数量会掩盖真实转化率。

## 进入产品 V1 的条件

只有满足以下条件，才进入自动化开发：

- 已确认一个主 ICP。
- 已出现真实的一次性付费。
- 已有一份用户认为“具体且值得交给开发者执行”的报告样例。
- 已决定视觉分析是否为 P0，并确认相应模型。
- 已确认评分 rubric、报告 JSON schema 和数据保留策略。
- 已接受 Next.js + Node Worker + Supabase 的最小架构。

## 开发 V1 的推荐边界

### P0

- 首页和 URL 提交。
- URL 安全校验。
- Playwright 首页抓取、结构化证据和截图。
- 异步分析状态。
- 文本证据版免费报告。
- 邮箱保存/发送。
- 一次性 Deep Audit 购买和报告解锁。
- 失败重试、限流、埋点和人工报告质量抽检。

### P1

- 多模态视觉分析。
- PDF 导出。
- 一个高质量 SEO 入口页。
- 前后复查和差异报告。

### P2

- 订阅。
- 变化追踪。
- 代理商/白标。
- 竞品监控。
- 自动修改网站。

## 主要风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 直接竞品已覆盖相似功能 | 很难靠功能列表脱颖而出 | 聚焦 SaaS 首页和证据优先的报告体验 |
| DeepSeek V4 不能直接看截图 | 截图卖点无法按原规格实现 | 文本证据版先行，视觉模型单独验证 |
| Playwright 任务超时或被目标站点拦截 | 分析完成率下降 | 独立 Worker、失败状态、超时和可访问性说明 |
| 报告泛化 | 用户不愿付费 | 先做页面证据、置信度和人工抽检 |
| 抓取任意 URL 带来 SSRF | 安全和基础设施风险 | P0 阻止私有地址、限制网络和资源 |
| $19 高于低价竞品 | 价格转化不足 | 先用 $9–$19 小实验验证，不先承诺订阅 |

## 最终判断

**推荐：先做小规模验证。**

该项目值得继续，因为它有清晰痛点、可展示的报告结果和可测试的一次性付费场景；但现在还不值得直接进入完整开发。下一步的成功标准不是“页面搭出来”，而是获得第一批真实付费，并确认用户愿意为具体、可信、能直接执行的改进建议买单。
