# AI Website Critic PRD 评审

评审对象：`PRD-ai-website-critic.md`。评审依据是项目目标、公开竞品扫描结果和 2026-08-10 查阅的官方技术资料。

## 评审结论

当前 PRD 可以支持一个真实的产品验证，但还不能直接作为完整 SaaS 的开发清单。核心问题不是功能不够，而是验证目标、截图能力、用户范围和付费节奏之间有几处冲突。

建议将 V1 分成两个含义：

- **验证 V1**：用最小的 URL 分析和人工/半自动 Deep Audit 验证“是否有人愿意付费”。
- **产品 V1**：只有验证出现真实购买后，才自动化完整报告和持续运营能力。

## 逐项评审

| 项目 | 当前规格 | 结论 | 优先级 | 调整建议 |
|---|---|---|---|---|
| 核心问题 | 网站为什么没人转化 | 保留 | P0 | 继续只围绕“下一步改什么”组织报告 |
| 用户范围 | Indie Hacker、小企业老板、设计师/营销人员 | 修改 | P0 | 首先锁定 Indie Hacker/小型 SaaS 创业者；设计师/代理商移到 P1 |
| URL 提交 | 输入公开网站 URL | 保留 | P0 | 只支持公开首页；明确失败和不可访问状态 |
| 60 秒承诺 | 60 秒内得到报告 | 修改 | P0 | 改为“目标约 60–120 秒”，上线前用 p50/p95 和失败率确认 |
| 首页抓取 | HTML、Meta、结构、文案、alt、CTA、Schema | 保留 | P0 | 这是第一版的主要证据来源 |
| 截图分析 | 把 Screenshot 作为 AI 输入 | 修改 | P0/P1 | 截图捕获可保留为 P0 证据；真正的视觉 AI 需另选多模态模型。DeepSeek V4 官方资料显示其为纯文本模型，不能默认支持截图输入 |
| Website Score | 100 分制 | 修改 | P0 | 先定义评分 rubric、权重和证据；没有校准前，显示“问题优先级”比伪精确分数更可靠 |
| 免费报告 | 基础分数、模块评分、关键问题 | 保留 | P0 | 免费层给总览、最大问题和少量 quick wins，不泄露完整行动计划 |
| Deep Audit | $19 一次，完整 UX/SEO/文案/结构/竞品 | 修改 | P0 验证 / P1 自动化 | 付费意愿必须在验证阶段出现；交付初期可以人工或半自动完成，不等 PDF 和全自动系统 |
| 邮箱收集 | 免费报告后收集邮箱 | 保留 | P0 | 先让用户看到有价值的结果，再用邮箱保存/发送报告，避免一上来强制注册 |
| 支付 | Week 3 才做 | 修改 | P0 验证 | 这是核心指标的一部分，应在付费实验中尽早出现；支付自动化可以晚于人工交付 |
| PDF 导出 | Week 2 | 降级 | P1 | 初次验证用网页报告或人工 PDF 即可，PDF 不应阻塞付费测试 |
| SEO 页面 | 5 个入口页 | 降级 | P1 | 先选 1 个页面验证搜索意图和提交率，不要一次创建 5 个薄页面 |
| X 增长 | 每日发布分析/案例/开发过程 | 修改 | P1 | 这是获客实验，不是产品需求；必须脱敏并征得网站所有者授权 |
| 订阅 | $19/月、每月分析和变化追踪 | 延后 | P2 | 只有出现复查需求后再做；目前先验证一次性购买 |
| 竞品定位分析 | Deep Audit 内容之一 | 降级 | P1 | 首先解释自身页面；竞品比较需要稳定 benchmark 和额外数据，不适合初始自动化强承诺 |
| SEO 范围 | 基础 SEO 问题 | 保留并限界 | P0 | 只做首页基础检查，不宣称完整 SEO 审计 |
| 数据保存 | 用户、分析、报告 | 补充 | P0 | 增加保存期限、原始 HTML 处理、截图访问权限和删除机制 |

## 发现的关键矛盾

### 1. 付费验证被排在开发计划后段

项目目标是验证用户是否愿意付费，但原计划把支付放在 Week 3。这样会先花时间做完整免费产品，再验证最关键的商业假设。调整为：先做能展示价值并收取一次性费用的最小实验，完整自动化随后进行。

### 2. DeepSeek 与截图输入不匹配

项目书要求输入 HTML、Screenshot 和 Metadata，但 DeepSeek 官方接入资料当前明确写明 DeepSeek V4 是纯文本模型；其 API 文档支持 JSON 输出，但不能据此推断支持图片输入。若视觉分析是核心卖点，需要另选或增加具备图像输入能力的模型，例如在技术评审中比较 OpenAI/Claude 等方案。

来源：[DeepSeek V4 视觉支持说明](https://api-docs.deepseek.com/quick_start/agent_integrations/github_copilot/)、[DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/)。

### 3. “60 秒”同时包含抓取、截图、AI 和报告渲染

这是性能目标，不是默认事实。竞品页面的速度口径也不一致：Web Anatomy 写“约 2 分钟”，Conversion Probe 写“约 1 分钟”，Landing Analyze 首页和 FAQ 对耗时的写法不一致。因此应先记录阶段耗时，再决定营销承诺。

### 4. 三类用户的购买理由不同

Indie Hacker 需要“为什么没人注册”，小企业老板需要“为什么没有客户”，代理商需要“如何给客户交付”。同一份报告很难同时满足三者。第一版先服务产品创始人，代理商白标和客户组合管理留到后续。

### 5. 一次性购买和订阅同时出现

一次性购买验证单次价值；订阅验证持续复查价值。两者的触发场景不同，初始规格不应同时优化。竞品中 Cruelx 已把两种场景分成 Full Report 和月度复查计划，说明这应是后续产品阶梯，而不是初始功能堆叠。

## 修订后的优先级

### P0：先验证价值和付费

- 面向一个明确 ICP 的落地页。
- URL 校验和公开首页抓取。
- 页面文本/Meta/结构/Schema/CTA 证据提取。
- 截图生成，但暂不承诺 DeepSeek 视觉理解。
- 免费报告：最大问题、影响原因、3 个 quick wins。
- 邮箱保存或发送报告。
- 一次性付费入口，Deep Audit 可以人工/半自动交付。
- 分析成功率、报告完成率、邮箱率、付费率、报告评分埋点。
- URL 抓取安全、限流和数据保留策略。

### P1：购买后自动化和增长

- 视觉 AI 或另一多模态模型。
- 完整 Deep Audit 自动化。
- PDF 导出。
- 一个有真实案例支撑的 SEO 入口页。
- 设计师/代理商交付格式。
- 前后改动比较。

### P2：重复使用和平台化

- 订阅。
- 网站变化追踪。
- 多站点管理。
- 白标 PDF。
- 复杂竞品监控。
- 网站自动修改。

## 建议的验证指标

除了原有数量目标，必须记录以下事件：

`home_viewed` → `url_submitted` → `analysis_completed` → `report_viewed` → `email_submitted` → `paid_started` → `paid_completed` → `report_opened` → `report_rated`

报告质量至少用四项人工评分：

1. 问题是否有页面证据。
2. 解释是否具体而非通用。
3. 改写是否能直接使用。
4. 优先级是否让用户知道先改什么。

## 评审后的产品边界

第一版不应承诺“完整网站审计”“提高转化率”或“竞争定位已被证明”。可以承诺的是：

> 根据公开首页的真实内容，找出最值得先改的转化问题，并给出可执行的改写和页面建议。
